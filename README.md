# OIBC 2026 태양광 집합자원 예측

2026 POSTECH OIBC Big Data Challenge. 과제는 태양광 발전소 253곳을 두 묶음(G1·G2, 각 20,000kW 이상)으로 나누고, 묶음별 시간 발전량을 하루 전에 예측하는 것이다.

- 점수(정산금): S = 수익 − 0.1 × Σ SMP × k × |묶음 예측 오차|. 11~15시는 k = 3이다.
- 수익은 모든 팀이 같으므로 순위는 예측 오차 벌금으로 갈린다.
- 대회는 2026-11-13에 끝났다.

> 이 브랜치(main)에는 우리 파이프라인(옛 `chloe-solo` 작업)이 있다. 팀원들이 만든 자료는 `team-archive` 브랜치에 그대로 보존되어 있다.

## 최종 파이프라인 (`E13-13ftx2_comp`)

### 입력

- **대회 제공 예보 A·B**: 10시·17시 두 발행분을 한 모델에 넣었다. 태양 고도·방위각과 설비용량도 쓴다.
- **예보 가공 피처**
  - 하루 요약 11개: 그날 운량, 일교차, 강수, 전날 강수 등이다.
  - A 운량·습도의 앞뒤 1시간·3시간 평균
- **외부 예보** (NOAA, AWS 공개 저장소)
  - GFS 0.5° 일사량, 전체·하층·중층·상층 운량을 1° 지역 42곳과 전체로 평균했다.
  - GEFS 앙상블 평균과 표준편차(퍼짐)
  - 모든 발전소에 같은 값을 넣었다.

### 앙상블 (6개 같은 비중)

| 구성원 | 모델 | 특징 |
|---|---|---|
| E11-12 | XGBoost | 맑은날 대비 비율(CSI)을 맞힘 |
| E11-11 | XGBoost | 발전율을 맞힘 |
| G5bT1 | LightGBM | GFS 층별 운량 포함, Optuna 설정 |
| S3 | LightGBM | 외부 예보 중심(GFS + GEFS 평균·퍼짐) |
| V07T1 | LightGBM | 대회 제공 예보만 |
| M2 | PyTorch MLP | 발전소 임베딩, GPU 학습 |

### 후처리와 구성

- **빠짐 처리**: 외부 예보가 비어 있는 시각에는 그 구성원을 빼고 남은 구성원끼리 다시 나눠 섞는다.
- **일출·일몰 보정**: 태양 고도 −4 ~ 0° 구간을 학습 기간 실측 발전율의 중앙값으로 채운다.
- **묶음 구성**: 앙상블 오차로 발전소를 하나씩 옮기는 탐색으로 정했다. G1은 126곳 21,576kW, G2는 127곳 21,079kW다(`outputs/compositions/E12-10cx2.csv`).

## 배운 점

1. **새 정보가 가장 컸다.**
   - GFS 하나로 +873만 원을 얻었다. 전체 개선의 47%다.
   - 내부 개선 폭이 리더보드에서도 그대로, 혹은 더 크게 나타났다.
2. **모델·설정 변경은 일부만 옮겨졌다.**
   - E11-10T1은 내부 −3.83%였지만 리더보드 개선은 기대의 절반 이하였다.
   - GEFS 교체(내부 −0.88%)는 리더보드에서 오히려 −53만 원이었다.
   - MLP(내부 −0.2%)는 +6만 원에 그쳤다.
   - 내부 1%는 리더보드 86 ~ 218만 원으로 옮겨졌고, 1% 안팎의 차이는 잡음 수준이었다.
3. **결정적 보정은 그대로 옮겨졌다.**
   - 일출·일몰 보정: 내부 약 −40만 원 → 리더보드 +38만 원
   - 빠짐 처리 버그 수정: +47만 원
4. **한 해만 보면 속는다.**
   - 맑은날 기준값(E3)은 2024-25에서만 좋아졌고, 리더보드에서 −300만 원이었다.
   - 세 해 검증은 이 방향을 미리 맞혔다. 그래서 이후 채택 규칙으로 계속 썼다.
5. **5위와의 약 1,213만 원은 좁히지 못했다.**
   - 남은 피처·모델 후보를 모두 통과시켜도 내부 −0.5 ~ −1.5% 수준이었다.
   - 차이는 우리가 찾지 못한 정보 출처나 처리 방식에 있었다고 본다.

## 규정 준수

- **외부 예보**: 전날 17:00 KST 전에 공개된 파일만 썼다.
  - 파일마다 AWS 공개 시각을 `outputs/*_manifest.csv`에 남겼다.
  - 마감 뒤 공개된 파일은 빈칸으로 처리했다.
- **고정 지역**: 외부 예보는 고정 지역 평균이라 모든 발전소에 같은 값이다.
- **SMP**: 대상일 SMP와 출력제어 공지는 쓰지 않았다. SMP 가중 실험에는 학습 기간 SMP만 썼다.
- **리더보드**: 배율·혼합 비중·구성은 내부 검증으로만 정했다. 리더보드를 보며 맞추지 않았다.
- **기타**: 좌표로 실제 위치를 찾지 않았고, 대회 데이터를 올리지 않았다.
- 규정 전문과 점검 내용은 [docs/대회_규정.md](docs/대회_규정.md)에 있다.

## 최종 제출 파일 만드는 순서

명령은 저장소 맨 위 폴더에서 실행한다.

### 1. 환경

- Python 3.10 이상에 `pandas pyarrow lightgbm xgboost torch optuna`를 설치한다.
- GFS 해석은 `pygrib`가 있는 별도 환경에서 돌린다.

### 2. 공통 테이블과 외부 예보 준비

1. `python src_tools/build_base.py`로 공통 테이블을 만든다.
2. GFS·GEFS를 받고 해석한다. 옵션은 각 파일 맨 위 설명에 있다.
   - 받기: `src_tools/gfs_fetch.py` (GFS 기본, `--source gefs`)
   - 해석: `src_tools/gfs_decode.py`

### 3. 구성원 예측과 제출 파일

구성원 6개를 실제 평가 기간으로 학습하고, 섞고, 보정한 뒤 제출 파일을 만든다.

```
for m in E11-12x2 E11-11x2 G5bT1x2 S3x2 V07T1x2 M2x2; do
  python src_tools/train_site_model.py --base $m --mode test
done
python src_tools/blend.py --out E13-13fx2 E11-12x2 E11-11x2 G5bT1x2 S3x2 V07T1x2 M2x2 --mode test
python src_tools/twilight_fix.py --preds E13-13fx2 --out E13-13ftx2
python src_tools/make_submission.py outputs/preds_test/E13-13ftx2.parquet --composition outputs/compositions/E12-10cx2.csv --name E13-13ftx2_comp
```

세 해 검증은 다음 순서로 한다.

1. 구성원을 `--mode test` 없이(2024-25) 학습하고, `--cut 2023-06-01`, `--cut 2022-06-01`로도 학습한다.
2. `blend.py`에 같은 `--cut`을 주어 섞는다.
3. `python src_tools/compare_years.py 기준 후보…`로 비교한다.
